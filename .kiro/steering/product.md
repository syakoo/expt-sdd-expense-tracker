# Product Overview

作業者が自分の領収書を登録し、複数の領収書をまとめて経費精算を申請する。申請時に指定された承認者が承認すると精算完了になる、小さな経費精算 Web アプリ。

同時に、Kiro スタイルの Spec-Driven Development を AI エージェント主導で試す実験リポジトリでもある。速度より、健全で見通しのよい設計を優先する。

## Core Capabilities

- **簡易ユーザー切替**：ログインなしで操作ユーザーを選び、作業者と承認者の立場を行き来する
- **領収書管理**：作業者が自分の領収書（日付・金額・支払先・費目・メモ）を登録・編集・削除・一覧する
- **申請ワークフロー**：複数の領収書を束ねて承認者を指定して申請し、承認／差し戻し／再申請を経て精算完了にする

## Target Use Cases

- 作業者が日々の領収書をためておき、まとめて精算を申請する
- 承認者が申請を確認し、コメント付きで差し戻すか承認する
- 開発者が 1 台のブラウザで両方の立場を切り替えながら、ワークフロー全体を確かめる

## Value Proposition

- 「申請の状態遷移」というドメインの核を 1 か所（expense-claim-workflow）に閉じ込め、深いモジュールとして扱う
- 認証や通知などの周辺を意図的に削り、spec 駆動の開発フローそのものを観察しやすくしている

## Out of Scope（プロダクトとして持たないもの）

本格的な認証・認可、領収書画像と OCR、多段階承認、実際の支払処理や会計連携、メールなどの通知。詳細と判断の理由は `roadmap.md` を参照。
